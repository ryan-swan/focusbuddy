## §1 · Amendments

### ⚠ A-01 · §1.1 — the quarantine is incomplete
**Spec said:** `task` / `taskId` means desk in code identifiers; the quarantine is the
mitigation.
**Verification found:** the contamination is broader in kind, not just in count. 244 `task`
occurrences across `src/main/ai`, and — decisively — `create-task` is a **`FlowActionType`
in user-authored, saved Flow automations**, plus wrapup, proposals, `MessagesView`, MindMap,
and Meet. It is a published cross-app protocol with user artifacts written against it. It is
also literal in prompts the model reads (`agentDispatcher.ts:144`, `discoveryMode.ts:32`,
gated at `creationGate.ts:33`), alongside a second surface, `create-todo-list`.
**Amendment — add a third quarantine row:**

| Term | Means, permanently | Never means |
|---|---|---|
| `create-task` *(wire/protocol)* | **Create a desk.** A published action kind with user-authored saved Flows depending on it. | Create a work_item. |

**Resolution is protocol quarantine, not rename.** The wire name is frozen. Every prompt
that mentions it gains an explicit definition. The new action is named `create-work-item` —
unmistakable, no alias, no overlap. Human-facing labels change to "Create desk," which fixes
the user-visible mislabeling the bug report actually reported.
**Do not rename `create-task`.** A rename — even aliased — breaks saved Flows their authors
cannot see and did not write. This supersedes SPEC-044's original "rename with compat alias"
framing.

### ⚠ A-02 · §1.5 — statuses do not live where the spec implies
**Spec said:** work_items carry the §1.5 status list (`waiting`, `needs_review`,
`needs_approval`, `delegated`, `blocked`, `suggested`, `stale`) and nine terminal states.
**Verification found:** work_items are nodes and inherit `nodes.status: TaskStatus`
(`open | in_progress | done | parked`) with **no database CHECK** — the collision is at the
TypeScript union and ~53 renderer comparison sites. Read literally, the spec instructs a
builder to widen that union or overload the column. **That is the `taskId` mistake,
repeated.**
**Amendment (GAP-012):** two columns, one source of truth.
- `work_item_state` — the canonical rich state machine of §1.5. Authoritative.
- `status` — a **coarse projection**, always one of the four legacy values, so every
  existing consumer reads something sane and is left untouched.

**The projection is derived, never independently written.** If both columns are writable
they drift, and a desk consumer reading `status = 'done'` on a work_item whose real state is
`needs_approval` produces a phantom completion in Pulse or a lens. Compute `status` at write
from `work_item_state`.
**SPEC-002 must publish the mapping table explicitly**, including the terminal-state
collapse. `dismissed` and `reclassified` are not completions and must not project to `done`.
No union widening. No discriminator overloading.

### A-03 · SPEC-002 — reference integrity is mandatory, and the danger is named
**Spec said:** SPEC-043 (source-reference integrity) is prudent design work.
**Verification found:** `nodes.parent_id REFERENCES nodes(id) ON DELETE CASCADE`
(`database.ts:32`), and `trashNode` recursively sweeps children by `parent_id` **with no
kind filter** (`db/nodes.ts:223`). Default behavior today: a work_item routed to you is
silently trashed — or cascade-deleted on the hard path — when the sender trashes their desk.
**Amendment:** SPEC-043 is upgraded from prudent to **mandatory at SPEC-002**. Field renames
in the SPEC-002 column list: `state` → `work_item_state`; `terminalState` folds into it.
**Partial answer already exists:** the shared-desk deletion guard required by DEC-013 is
share-blind today, and building it closes this danger for shared desks with the same
mechanism. One guard, two problems. SPEC-043's remaining scope is the non-shared case.

### A-04 · SPEC-004 — the census gains a confirmed target and a conditional one
**Confirmed Class C:** `trashNode`'s recursive child sweep (`db/nodes.ts:223`) is a named,
verified unfiltered enumeration. Add to the must-touch list before classification begins.
**Conditional:** BUG-C1-03 (shared desks in the wrong tab) is **not** confirmed as an
enumeration bug. `sharedFromHandle` has zero hits in `Sidebar.tsx` and `stores/nodes.ts`;
the filter lives elsewhere. It serves as the census's validation case **only if triage
proves enumeration**.
**Note the other branch is worse for this build.** If the root cause is metadata stamping —
desks arriving via org sync never getting share metadata applied — that is a direct
precedent for routed work_items arriving without their routing fields. Triage informs
Phase 2 either way; the "boring" outcome is the one to worry about.
*(Post-drafting note: triage completed in analysis/10 §6 — root cause proven to be
two-source enumeration with metadata correctly stamped; the census method is validated as a
ground-truth positive, and the metadata-stamping fear did not materialize.)*

### A-05 · §8 Q5 — struck; now ruled
**Q5 (delete semantics) is closed by DEC-013.** Archive is first-class (visual cleanup,
memory intact). Deletion presents an explicit choice: preserve in memory vs. delete
permanently. Shared desks are protected from unilateral deletion; the v1 default returns for
design approval.
**Scope correction in the operator's favor:** trash and memory are **already separate
systems** — `trashed_at` soft-delete and restore never touch the brain. "Trash the desk,
keep the memory" is close to de facto behavior today, merely unexposed and uncontracted. The
genuinely new machinery is **memory purge** and the **shared-desk delete guard**. Q5 was
priced as a design problem; it is largely a matter of stating and exposing what the system
already does.
§8 Q1–Q4 and Q6–Q8 remain open as written.
